Positional Encoding ကို နာရီလက်တံနဲ့နှိုင်းယှဥ်ပြီး နားလည်အောင် အဖြေထုတ်ကြည့်မယ်

Attention Is All You Need (Vaswani et al., 2017) စာတမ်းထဲက sin/cos ညီမျှခြင်းတွေ ဘယ်ကလာလဲ

Prerequisites: Tokenization, Embedding, Cosine Similarity

Positional encoding အကြောင်းဆွေးနွေးကြတာပေါ့။

ကျွန်တော်တို့ စကားပြောတဲ့ အခါ ဘာပြီးရင် ဘာလာတယ်ဆိုတဲ့ စာလုံးအထားအသိုက အရေးကြီးတယ် မလား?

ဆိုပါစို့။ "Dog bites man" (ခွေးက လူကို ကိုက်တယ်) ဆိုတာနဲ့ "Man bites dog" (လူက ခွေးကို ကိုက်တယ်) ဆိုတာက မတူဘူး ဟုတ်?

ဒါပေမယ့် AI တွေရဲ့ ပထမအဆင့် encoding မှာက Dog အတွက် ဂဏန်းအစု (vector) တစ်ခု၊ bites အတွက် တစ်ခု၊ man အတွက် တစ်ခုဆိုပြီး စာလုံးတစ်လုံးချင်းစီကို သီးသန့်ပြောင်းလိုက်တာပါ။ စာလုံးတွေ ဘယ်အစီအစဥ်နဲ့ လာလဲဆိုတာ အဲဒီအဆင့်မှာ မသိသေးဘူး။

Dog bites manခွေးက လူကို ကိုက်တယ်
Man bites dogလူက ခွေးကို ကိုက်တယ်

စာလုံး အတူတူ၊ အစီအစဥ်ပဲ ကွာတယ်၊ အဓိပ္ပါယ်ကတော့ လုံးဝ ကွာတယ်

နေရာ အချက်အလက် မပါရင် ဘာဖြစ်လဲ

စမ်းကြည့်ရအောင်။ ညာဘက်က model က query တွေအတွက် Transformer မသုံးဘဲ စာလုံးတစ်လုံးချင်းရဲ့ အလေးချိန် (weight) ကို ဇယားထဲကနေ ရှာယူတာပါ။

ဂဏန်းတွေ အတိအကျ တူနေတယ်။ Cosine similarity က 1.0 ဆိုတော့ ဒီ model အတွက် "ခွေးက လူကို ကိုက်တာ" နဲ့ "လူက ခွေးကို ကိုက်တာ" ဟာ လုံးဝ အတူတူပဲ။ စာလုံးတွေ တူပြီး အစီအစဥ်ပဲ ကွာတဲ့အတွက် ဘာမှ ခွဲခြားလို့ မရဘူး။

ကုဒ်

from sentence_transformers import SparseEncoder

model = SparseEncoder("opensearch-project/opensearch-neural-sparse-encoding-multilingual-v1")

e1 = model.encode_query("Dog bites man")
e2 = model.encode_query("Man bites dog")

v1 = e1.coalesce().values()
v2 = e2.coalesce().values()

print("Dog bites man:", v1.cpu().numpy())
print("Man bites dog:", v2.cpu().numpy())
print("Cosine similarity:", (model.similarity(e1, e2) / (v1.norm() * v2.norm())).item())

ရလဒ်

Dog bites man: [2.082 2.975 4.386]
Man bites dog: [2.082 2.975 4.386]
Cosine similarity: 1.0

နေရာ (position) အချက်အလက်ကို ထည့်ပေးထားတဲ့ Transformer model တစ်ခုနဲ့ စမ်းကြည့်ရင်ရော?

ဒီတစ်ခါတော့ ဂဏန်းတွေ မတူတော့ဘူး။ Similarity က 0.907 ပါ။ စာလုံးတွေ အကုန်တူလို့ နီးစပ်နေသေးပေမယ့် အစီအစဥ် ကွာသွားတာကို model က သတိထားမိတယ်။ ဒီလို ခွဲခြားနိုင်အောင် လုပ်ပေးတဲ့ အရာတွေထဲက အဓိကတစ်ခုက positional encoding ပါပဲ။

ကုဒ်

import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

emb = model.encode(["Dog bites man", "Man bites dog"])
np.set_printoptions(precision=3, suppress=True)

print("Shape:", emb.shape)                       # (2, 384)
print("Dog bites man (first 10):", emb[0][:10])
print("Man bites dog (first 10):", emb[1][:10])
print("Cosine similarity:", model.similarity(emb[0], emb[1]).item())

ဒီတော့ မေးစရာက နေရာအချက်အလက်ကို encoding ထဲ ဘယ်လိုထည့်မလဲ?

ပထမစာကြောင်း 'Dog bites man' အတွက် Dog က နေရာ ၁ (pos 0), bites က နေရာ ၂ (pos 1), man က နေရာ ၃ (pos 2) လို့ထားပြီး နည်းလမ်းအမျိုးမျိုးနဲ့ နေရာသတ်မှတ်ချက်ကို encoding ထဲ ထည့်ဖို့ ကြိုးစားကြည့်ရအောင်။

bitespos 1
manpos 2
---
Manpos 0

ပထမနည်းလမ်း: နေရာနံပါတ်ကို တိုက်ရိုက်သုံးမယ်

ဆိုပါစို့ pos 0 ဆိုရင် 0၊ pos 1 ဆိုရင် 1၊ pos 200 ဆိုရင် 200 ဆိုပြီး၊ ရလာတာတွေကို အပေါ်က encoding နဲ့ ပေါင်းလိုက်မယ်။ အပေါ်မှာ မြင်ခဲ့သလို encoding ထဲက ဂဏန်းတွေက 0.1 လောက်ပဲ ရှိကြတာ။ အဲဒီမှာ 200 ပေါင်းလိုက်ရင် 200 ကျော်တွေ ဖြစ်ကုန်ပြီး position က စာလုံးရဲ့ အဓိပ္ပါယ်တွေကို ဖုံးသွားမယ်။ ဒီတော့ တခြားနည်းလိုလာရော။

ဥပမာ: embedding ထဲက ဂဏန်း ၃ လုံးကို pos 200 နဲ့ ပေါင်းရင်

= result:  [ 200.059 200.069 199.975 ]   ← စာလုံးရဲ့ အချက်အလက် တွေက

ဒုတိယနည်းလမ်း: Binary (0 နဲ့ 1)

နေရာနံပါတ်ကို binary နဲ့ ရေးကြည့်ရင်ရော? ဒီလိုဆို ဂဏန်းတွေက 0 နဲ့ 1 ပဲ ရှိတော့ ရှိပြီးသား encoding value တွေနဲ့ အရမ်း မကွာတော့ဘူး ဟုတ်?

ဒါပေမယ့် binary မှာလည်း ပြဿနာ ရှိသေးတယ်။

  • ဂဏန်းတွေက 0 ကနေ 1, 1 ကနေ 0 ဆိုပြီး ပြောင်းတာက အရမ်းမြန်နေတယ်။ Neural network တွေက တဖြည်းဖြည်း ချောချောမွေ့မွေ့ ပြောင်းလဲတဲ့ ဂဏန်းတွေနဲ့ ပိုအလုပ်ဖြစ်တယ်။
  • ဂဏန်းတစ်ခုစီက ဒဿမကိန်း သိမ်းနိုင်တယ်။ ခုက 0 ဒါမှမဟုတ် 1 ပဲ သိမ်းထားတော့ နေရာ ဖြုန်းသလိုလည်း ဖြစ်နေတယ်။
pos 0:  0 0 0 0
pos 1:  0 0 0 1
pos 2:  0 0 1 0
pos 3:  0 0 1 1
pos 4:  0 1 0 0
pos 5:  0 1 0 1
pos 6:  0 1 1 0
pos 7:  0 1 1 1

binary နည်းလမ်းရဲ့ ပြသနာတွေကို ဖြေရှင်းဖို့ binary ဇယားထဲမှာ အရေးကြီးတဲ့ အချက်တစ်ခု ကြည့်ရအောင်။ Row တွေကို မကြည့်ဘဲ column တွေကို ကြည့်ကြည့်ပါ။

  • ညာဘက်ဆုံး column က 0, 1, 0, 1 ဆိုပြီး အဆင့်တိုင်း ပြောင်းနေတယ်။
  • သူ့ဘေးဘယ်ဖက်က column က အဆင့် ၂ ဆင့်တစ်ခါ ပြောင်းတယ် (0, 0, 1, 1, ...)။
  • နောက်တစ်ခုက အဆင့် ၄ ဆင့်တစ်ခါ ပြောင်းတယ်။

Column တစ်ခုချင်းက တက်လိုက် ဆင်းလိုက် ဖြစ်နေတဲ့ လှိုင်း (wave) တစ်ခုလိုပဲ၊ ပြီးတော့ တစ်ခုထက်တစ်ခု ပိုနှေးတယ်။ ဒါက နောက်နည်းလမ်းရဲ့ သော့ချက်ပဲ။

Binary column တစ်ခုချင်းကို pos 0 ကနေ 15 အထိ ဆွဲကြည့်ထားတာ

sin က လှိုင်းတွေကို ဘယ်လို ထုတ်ပေးလဲ

တတိယနည်းလမ်းကို မသွားခင် လှိုင်းတွေ ထုတ်ပေးတဲ့ sin ဆိုတာကို အရင် နည်းနည်း သိထားရအောင်။

စက်ဝိုင်းတစ်ခုမှာ နာရီလက်တံလိုမျိုး လက်တံတစ်ခု လည်နေတယ်လို့ စဥ်းစားကြည့်ပါ။ လက်တံက ၁၂ နာရီ နေရာကနေ စပြီး နာရီလှည့်တဲ့ဘက်ကို လည်မယ်။ လက်တံထိပ်က အလယ်ကနေ ညာဘက်ကို ဘယ်လောက် ရောက်နေလဲ ဆိုတဲ့ ဂဏန်းကို sin လို့ ခေါ်တယ်။ ညာဘက် အစွန်းဆုံးရောက်ရင် 1၊ ဘယ်ဘက် အစွန်းဆုံးရောက်ရင် −1၊ တည့်တည့် အပေါ် ဒါမှမဟုတ် အောက်ဆိုရင် 0။

လက်တံ လည်သွားသလောက် ဒီဂဏန်းကို ဂရပ်ပေါ်မှာ ဆက်တိုက် ချရေးသွားရင် တက်လိုက် ဆင်းလိုက် လှိုင်းတစ်ခု ထွက်လာတယ်။ အဲဒါ sin လှိုင်းပါပဲ။ ညာဘက်က slider ကို ဆွဲကြည့်ပါ။

π (pi) နဲ့ radian

လက်တံ ဘယ်လောက် လည်သွားပြီလဲ (ထောင့်) ကို တိုင်းဖို့ ကျွန်တော်တို့ ပုံမှန်အားဖြင့် degree (°) ကို သုံးတယ်၊ တစ်ပတ်ပြည့်ရင် 360°။ သင်္ချာနဲ့ programming မှာတော့ radian ဆိုတဲ့ ယူနစ်ကို ပိုသုံးကြတယ်။

အရင်ဆုံး π (pi) က ဂဏန်းတစ်ခုပါ၊ 3.14159... ။ ဘယ်စက်ဝိုင်းမဆို ပတ်ပတ်လည် အရှည် (အဝန်း) ဟာ အချင်းရဲ့ π ဆ အမြဲ ဖြစ်တယ်။ အချင်းဝက် (radius) 1 ရှိတဲ့ စက်ဝိုင်းဆိုရင် အချင်းက 2 ဖြစ်လို့ အဝန်းက 2π (6.28 လောက်) ဖြစ်တယ်။

Radian ဆိုတာ လက်တံထိပ် ဖြတ်သွားတဲ့ စက်ဝိုင်းမျဥ်းကွေးရဲ့ အရှည်နဲ့ ထောင့်ကို တိုင်းတာ (အချင်းဝက် 1 ရှိတဲ့ စက်ဝိုင်းမှာ)။ ဒါကြောင့်:

  • တစ်ပတ်ပြည့် = 2π radian = 360°
  • တစ်ဝက် = π radian = 180°
  • လေးပုံတစ်ပုံ = π/2 radian = 90°
  • 1 radian = 57° လောက်

ဒါကြောင့် sin(1) လို့ ရေးရင် "1 radian (57° လောက်) လည်ထားတဲ့ လက်တံ ညာဘက် ဘယ်လောက်ရောက်လဲ" လို့ မေးတာ။ အဖြေက 0.841၊ ဒဿမကိန်း ထွက်တာ ဒါကြောင့်ပါ။

အရေးကြီးတဲ့ အချက်က sin က 2π တစ်ခါ ပြန်ထပ်တယ်။ တစ်ပတ်ပြည့်ရင် အစနေရာ ပြန်ရောက်လို့ပါ။ sin(2π) = sin(0) = 0၊ sin(2π + 1) = sin(1)။

လှိုင်းကို နှေးအောင် ဘယ်လိုလုပ်မလဲ

sin ထဲကို ထည့်တဲ့ ဂဏန်းကို တစ်ခုခုနဲ့ စားလိုက်ရင် လှိုင်း နှေးသွားတယ်။ ဥပမာ sin(x/2) ဆိုရင် x က 2 တိုးမှ ထောင့်က 1 ပဲ တိုးတော့ လက်တံက တစ်ဝက်နှုန်းနဲ့ပဲ လည်တယ်။ တစ်ပတ်ပြည့်ဖို့ 2π မဟုတ်တော့ဘဲ 2π × 2 = 4π လိုတယ်။

  • sin(x) → 2π (6.3 လောက်) တစ်ခါ ပြန်ထပ်
  • sin(x/2) → 4π (12.6 လောက်) တစ်ခါ ပြန်ထပ်
  • sin(x/4) → 8π (25.1 လောက်) တစ်ခါ ပြန်ထပ်

ညာဘက်က လှိုင်း ၃ ခုကို binary column တွေရဲ့ square wave ပုံနဲ့ နှိုင်းယှဥ်ကြည့်ပါ။ တစ်ခုထက်တစ်ခု ၂ ဆ နှေးတာ အတူတူပဲ၊ ကွာတာက ဒီလှိုင်းတွေက ရုတ်တရက် မခုန်ဘဲ ချောချောမွေ့မွေ့ ပြောင်းတာပါ။

စည်းမျဥ်းကို မှတ်ထားပါ: ကြီးတဲ့ ဂဏန်းနဲ့ စားလေ လှိုင်း နှေးလေ။ ဒီ idea ကို နောက်က ညီမျှခြင်းထဲမှာ ပြန်တွေ့ရမယ်။

x ကို 0 ကနေ 8π အထိ

Positional encoding ညီမျှခြင်းနဲ့ မိတ်ဆက်မယ်

အခု paper ထဲက positional encoding ညီမျှခြင်းကို ကြည့်လိုက်ရအောင်။

ဟာ ဒါကြီး ဘာကြီးလဲ ကြောက်စရာကြီး...။ မကြောက်ပါနဲ့ အဲလောက်ကြီး ခက်တဲ့ အရာမဟုတ်ပါဘူး၊ အပေါ်မှာ သိခဲ့တာတွေနဲ့တင် အများကြီး ဖတ်လို့ရနေပြီ။

  • sin နဲ့ cos: လှိုင်းတွေ ထုတ်ပေးတဲ့ function တွေ။ cos ကလည်း sin လိုပဲ လှိုင်းပုံစံပါ။ ကွာတာက sin က 0 ကနေ စပြီး cos က 1 ကနေ စတယ် (လက်တံရဲ့ အပေါ်/အောက် ဂဏန်း)။
  • pos: စာလုံးရဲ့ နေရာ (0, 1, 2, ...)။ ဒါက လှိုင်းထဲကို ထည့်တဲ့ x ပါပဲ။
  • pos ကို 100002i/d_model နဲ့ စားထားတယ်: အခုလေးတင် သိခဲ့သလို ကြီးတဲ့ဂဏန်းနဲ့ စားရင် လှိုင်း နှေးသွားတယ်။ i ကြီးလာလေ စားတဲ့ဂဏန်း ကြီးလေ၊ လှိုင်း နှေးလေ။ Binary column တွေ ဘယ်ဘက်ရောက်လေ နှေးလေ ဆိုတာနဲ့ အတူတူပဲ။
  • 2i နဲ့ 2i+1: dimension နံပါတ်။ စုံကိန်း dimension (0, 2, 4, ...) မှာ sin၊ မကိန်း dimension (1, 3, 5, ...) မှာ cos။

ဒါပဲ! ဒီညီမျှခြင်းက "dimension တစ်ခုစီကို အမြန်နှုန်း မတူတဲ့ လှိုင်းတစ်ခုစီ ပေးလိုက်" လို့ ပြောနေတာပါ။ ညာဘက်က ဇယားမှာ d_model = 512 အတွက် i အချို့မှာ ဘယ်ဂဏန်းနဲ့ စားရလဲ ပြထားတယ်။

ဘာလို့ sin နဲ့ cos ကို အတွဲလိုက် သုံးတာလဲ၊ ဘာလို့ 10000 လဲ ဆိုတာကိုတော့ နောက်ပိုင်းမှာ နာရီလက်တံနဲ့ တစ်ဆင့်ချင်း ကြည့်သွားမယ်။

PE(pos, 2i) = sin( pos / 100002i / d_model )
PE(pos, 2i+1) = cos( pos / 100002i / d_model )

အဖွင့်အပိတ် (0/1) column တွေကို တဖြည်းဖြည်း တက်လိုက်ဆင်းလိုက် ဖြစ်တဲ့ လှိုင်းတွေနဲ့ အစားထိုးကြည့်ရအောင်။ ရှေ့ပိုင်း dimension တွေမှာ မြန်တဲ့လှိုင်း၊ နောက်ပိုင်းမှာ တဖြည်းဖြည်း နှေးလာတဲ့ လှိုင်းတွေ။ paper က သုံးတဲ့ နည်းလမ်းက ဒါပါပဲ။

နာရီလက်တံနဲ့ စဥ်းစားကြည့်မယ်

နာရီကို စဥ်းစားကြည့်ပါ။ စက္ကန့်လက်တံ၊ မိနစ်လက်တံ၊ နာရီလက်တံ ရှိတယ်။ လက်တံတွေက ဘယ်တော့မှ "ကြီး" မလာဘူး၊ လည်နေရုံပဲ။ စက္ကန့်လက်တံ တစ်ခုတည်းကိုပဲ ကြည့်ရင် ဒီတိုင်းကြီး ပတ်ချာလည်နေတာပဲမလို့ အချိန်အတိအကျ မသိနိုင်ဘူး။ ဒါပေမယ့် လက်တံသုံးခုလုံးကို တွဲကြည့်ရင် အချိန်အတိအကျ သိတယ်။

Positional encoding လည်း ဒီအတိုင်းပဲ။ နေရာတစ်ခုချင်းစီမှာ လက်တံ အများကြီး ပါတဲ့ နာရီတစ်လုံး ရှိတယ် (d_model = 512 ဆိုရင် လက်တံ 256 ခု ရှိတဲ့ နာရီလို့ စဥ်းစားလို့ရတယ်)။ စာလုံးတစ်လုံး ညာဘက်ကို ရွှေ့တိုင်း လက်တံတိုင်း နည်းနည်းစီ လည်တယ်။ မြန်တဲ့လက်တံက များများလည်ပြီး နှေးတဲ့လက်တံက နည်းနည်းလေးပဲ လည်တယ်။

  • မြန်တဲ့ လက်တံတွေက ဘေးချင်းကပ်နေတဲ့ စာလုံးတွေ (pos 5 နဲ့ pos 6) ကို ခွဲခြားပေးတယ်။
  • နှေးတဲ့ လက်တံတွေက ဝေးဝေးက စာလုံးတွေ (pos 5 နဲ့ pos 500) ကို ခွဲခြားပေးတယ်။

ညာဘက်က animation မှာ လက်တံ ၄ ခုကို ရွေးပြထားတယ် (d_model = 128 နဲ့)။ နာရီတစ်ခုစီဘေးမှာ အဲဒီလက်တံရဲ့ လှိုင်းနဲ့ ဂဏန်းတွေ ပါတယ်။ Slider ကို ဆွဲပြီး နေရာ အမျိုးမျိုး စမ်းကြည့်လို့ရတယ်။

sin နဲ့ cos ဆိုတာ ဘာလဲ

ဒါက လိုအပ်တဲ့ သင်္ချာ တစ်ခုတည်းပါ၊ ထင်ထားသလောက် မခက်ပါဘူး။ လက်တံ ဘယ်ဘက်ကို ညွှန်နေလဲဆိုတာကို ဂဏန်းနဲ့ ပြောချင်ရင် နှစ်ခု ပြောရမယ်။ လက်တံထိပ်က အလယ်ကနေ ဘယ်/ညာ ဘယ်လောက်ဝေးလဲ၊ အပေါ်/အောက် ဘယ်လောက်ဝေးလဲ။ sin နဲ့ cos ဆိုတာ ဒီဂဏန်းနှစ်ခုပါပဲ (x, y လို့ မြင်လို့ရတယ်)။

ဒီဂဏန်းတွေက −1 နဲ့ 1 ကြားမှာပဲ အမြဲရှိတယ်။ ဒါကြောင့် ပထမနည်းလမ်းမှာ ကြုံခဲ့တဲ့ "200 က အဓိပ္ပါယ်ကို ဖုံးသွားတယ်" ဆိုတဲ့ ပြဿနာ မရှိတော့ဘူး။ ပြီးတော့ ဒဿမကိန်းတွေ ဖြစ်တဲ့အတွက် binary လို ရုတ်တရက် ပြောင်းတာမျိုး မဖြစ်တော့ဘူး။

Animation မှာ pos 0 ဆိုရင် ဘာလို့ (0, 1) ချည်းပဲ ဖြစ်နေလဲ? ပထမဆုံး စာလုံးမှာ ဘယ်လက်တံမှ မလည်ရသေးလို့ အားလုံး တည့်တည့်အပေါ်ကို ညွှန်နေတာပါ၊ ၁၂ နာရီ ထိုးနေတဲ့ နာရီလိုပဲ။

သင်္ချာအတန်းမှာ သင်ခဲ့တာနဲ့ မတူဘူးလား?

သင်္ချာအတန်းမှာ များသောအားဖြင့် x = cos, y = sin လို့ သင်ပြီး ညာဘက် (၃ နာရီ) နေရာကနေ စတယ်။ ဒီမှာတော့ နာရီအစစ်လို ၁၂ နာရီကနေ စအောင် sin ကို ဘေးတိုက်၊ cos ကို အပေါ်အောက် ထားလိုက်တာပါ။ စက်ဝိုင်းက အတူတူပဲ၊ လေးပုံတစ်ပုံ လှည့်ထားရုံပဲ။ Paper ထဲမှာ sin ကို အရင်ရေးတဲ့ အစီအစဥ်နဲ့လည်း ကိုက်တယ်။

(sin, cos) = လက်တံထိပ်ရဲ့ (ညာ/ဘယ်, အပေါ်/အောက်)

လက်တံတွေ ဘယ်လောက် မြန်လဲ၊ 10000 က ဘာလဲ

d_model = 512 မှာ အမြန်ဆုံး လက်တံက စာလုံး ၆ လုံးလောက်မှာ တစ်ပတ်ပြည့်တယ်။ အနှေးဆုံးကတော့ စာလုံး ၆၀,၀၀၀ ကျော်ကြာမှ တစ်ပတ်ပြည့်တယ်။ ကြားထဲက လက်တံတွေက တစ်ခုထက်တစ်ခု ၃.၆% လောက်စီ ပိုနှေးတယ်။ Binary မှာ column တစ်ခုထက်တစ်ခု ၂ ဆ နှေးသလိုပဲ၊ ဒီမှာတော့ ပိုပြီး ညင်ညင်သာသာ နှေးသွားတာ။

10000 ဆိုတာ အနှေးဆုံးလက်တံ ဘယ်လောက်နှေးမလဲ သတ်မှတ်ပေးတဲ့ ဂဏန်းပါ။ ပုံမှန် စာကြောင်းတစ်ကြောင်းအတွင်း လက်တံအားလုံး တစ်နေရာတည်းကို ပြန်မရောက်အောင် (နေရာနှစ်ခု တူမသွားအောင်) လုံလောက်အောင် ကြီးဖို့ပဲ လိုတာ။ 10000 အတိအကျမှာ နက်နဲတဲ့ အဓိပ္ပါယ် မရှိဘူး၊ စာရေးသူတွေ ရွေးလိုက်တဲ့ ဂဏန်းပါ။

d_model = 512 မှာ လက်တံ အချို့ တစ်ပတ်ပြည့်ဖို့ လိုတဲ့ စာလုံးအရေအတွက်

တစ်ပတ်ပြည့်ဖို့ = 2π × 100002i / d_model

ညီမျှခြင်းကို အပိုင်းလိုက် ပြန်ဖတ်ကြည့်မယ်

အစောပိုင်းက ကြောက်စရာကောင်းတယ်လို့ ထင်ခဲ့တဲ့ ညီမျှခြင်းကို နာရီလက်တံ အမြင်နဲ့ ပြန်ဖတ်ကြည့်ရအောင်။ အခုဆို အပိုင်းတိုင်းရဲ့ အဓိပ္ပါယ်ကို သိနေပြီ။

  • pos = စာလုံးရဲ့ နေရာ (0, 1, 2, ...)
  • i = လက်တံ နံပါတ် (d_model = 512 ဆိုရင် 0 ကနေ 255 အထိ)
  • 2i (စုံကိန်း dimension) မှာ sin၊ 2i+1 (မကိန်း dimension) မှာ cos။ ဆိုလိုတာက လက်တံတစ်ခုစီအတွက် ဂဏန်း ၂ ခု ဘေးချင်းကပ်ရေးတာ။
  • 100002i/d_model = ဒီလက်တံ ဘယ်လောက် နှေးလဲ။ i ကြီးလေ နှေးလေ။
  • pos / 100002i/d_model = ဒီနေရာမှာ လက်တံ ဘယ်လောက် လည်သွားပြီလဲ (ထောင့်)။

တစ်ကြောင်းတည်းနဲ့ ပြောရရင်: လက်တံ တစ်ခုချင်းစီအတွက် ညာ/ဘယ် ဂဏန်း (sin) နဲ့ အပေါ်/အောက် ဂဏန်း (cos) ကို ချရေးလိုက်တာပါပဲ။

PE(pos, 2i) = sin( pos / 100002i / d_model )
PE(pos, 2i+1) = cos( pos / 100002i / d_model )

Python နဲ့ ရေးရင်

import numpy as np

def positional_encoding(max_len, d_model):
    pe = np.zeros((max_len, d_model))
    pos = np.arange(max_len)[:, None]          # (max_len, 1)
    i = np.arange(d_model // 2)[None, :]       # (1, d_model/2)
    angle = pos / 10000 ** (2 * i / d_model)   # လက်တံ ထောင့်
    pe[:, 0::2] = np.sin(angle)                # စုံကိန်း dimension
    pe[:, 1::2] = np.cos(angle)                # မကိန်း dimension
    return pe

print(positional_encoding(4, 4).round(3))

စာလုံးတစ်လုံးအတွက် ဂဏန်း 512 လုံးကို တစ်တန်းတည်း ဆက်တိုက် စီထားတယ်။

ဒါကြောင့် စာလုံး p လုံးရှိရင် PE matrix က (p, d_model) = (p, 512) ဖြစ်တယ်။ (p, 256, 2) လို့ စိတ်ထဲမှာ မြင်ကြည့်လို့ရပေမယ့် 256 × 2 = 512 ဆိုတော့ (p, d_model, 2) မဟုတ်ဘူး။ Word embedding တွေလည်း (p, 512) ဖြစ်လို့ shape တူတဲ့အတွက် တစ်လုံးချင်း ပေါင်းလို့ရတယ်။

pos 0: [sin₀, cos₀, sin₁, cos₁, sin₂, cos₂, …, sin₂₅₅, cos₂₅₅]   ← 512 လုံး
pos 1: [ … ပုံစံ အတူတူ … ]
  ⋮
pos p-1: [ … ]

PE shape:         (p, 512)
embedding shape:  (p, 512)
input = embedding + PE   → (p, 512)

အတော်လေး မိုက်တဲ့အပိုင်း

နာရီမှာ "၂ နာရီ နောက်ကျ" ဆိုရင် အခု ၁ နာရီဖြစ်ဖြစ် ၉ နာရီဖြစ်ဖြစ် နာရီလက်တံကို အတူတူပဲ လှည့်ရတယ်။

Positional encoding မှာလည်း ဒီအတိုင်းပဲ။ "ခုကနေစ နောက် စာလုံး ၃လုံး ဒါမှမဟုတ် နောက်တနေရာကစ နောက် စာလုံး၃လုံ့း" ဆိုတာ စာကြောင်းရဲ့ ဘယ်နေရာကနေ စစ လက်တံတိုင်းကို တူညီတဲ့ ပမာဏ လှည့်တာပဲ။ ဒါကြောင့် model က "ဒီစာလုံးကို ဒါနဲ့တွဲ ဒါပြီးရင် ဒါလာ" ဆိုတဲ့ စည်းမျဥ်းမျိုးကို လွယ်လွယ်ကူကူ သင်ယူနိုင်ပြီး စာကြောင်းရဲ့ အစ၊ အလယ်၊ အဆုံး ဘယ်နေရာမှာမဆို အလုပ်ဖြစ်တယ်။ (ဥပမာ adjective က noun ရှေ့မှာ လာတာမျိုး။)

Paper ကလည်း ဒီအချက်ကြောင့် ဒီ ဒီဇိုင်းကို ရွေးထားတယ်လို့ ပြောတယ်။ ဘယ် offset k အတွက်မဆို PE(pos+k) ကို PE(pos) ရဲ့ linear function အဖြစ် ရေးလို့ရတဲ့အတွက် model က relative position ကို လွယ်လွယ် သင်ယူနိုင်မယ်လို့ စာရေးသူတွေ မျှော်လင့်ခဲ့တာပါ။

သင်္ချာ စိတ်ဝင်စားသူတွေအတွက် ညာဘက်မှာ သက်သေပြချက် ပါတယ်။ အလယ်က matrix က rotation (လှည့်ခြင်း) matrix ဖြစ်ပြီး k ပေါ်မှာပဲ မူတည်တယ်၊ p ပေါ်မှာ မမူတည်ဘူး။ sin တစ်ခုတည်းနဲ့ဆို cos(ωp) ကိုပါ လိုလို့ ဒီလို ရေးလို့မရဘူး၊ ဒါကြောင့် sin နဲ့ cos အတွဲလိုက် သုံးရတာ။ နောက်ဆုံးညီမျှခြင်းအရ နေရာနှစ်ခုရဲ့ ဆင်တူမှုက အကွာအဝေး k ပေါ်မှာပဲ မူတည်တယ်။

ထောင့်ပေါင်း ပုံသေနည်း (ω = လက်တံ အမြန်နှုန်း)

sin(ω(p+k)) = sin(ωp)·cos(ωk) + cos(ωp)·sin(ωk)
cos(ω(p+k)) = cos(ωp)·cos(ωk) − sin(ωp)·sin(ωk)

Matrix နဲ့ ရေးရင်

[ sin ω(p+k) ]   [  cos ωk   sin ωk ] [ sin ωp ]
[ cos ω(p+k) ] = [ −sin ωk   cos ωk ] [ cos ωp ]
                  └── k ပေါ်မှာပဲ မူတည် ──┘

နေရာနှစ်ခုရဲ့ dot product

PE(p) · PE(p+k) = Σi cos(ωi k)

ဘာလို့ စာလုံး encodig နဲ့ နေရာ encoding ကို မြှောက်တာ မဟုတ်ဘဲ ပေါင်းတာလဲ၊

PE ဂဏန်းတွေထဲမှာ 0 (သို့) 0 နီးပါး ဖြစ်တာ အများကြီးပါတယ်။ pos 0 မှာဆို sin ဂဏန်းတွေ အားလုံး (တစ်ဝက်) က 0 အတိအကျပဲ။

မြှောက်ရင် ပထမဆုံး စာလုံးရဲ့ အဓိပ္ပါယ် တစ်ဝက်လောက် ပျက်သွားမှာ။ ပေါင်းတာကတော့ နာမည်ကတ်ပေါ်က ထောင့်လေးမှာ ထိုင်ခုံနံပါတ် ရေးလိုက်သလိုပဲ။ နာမည်လည်း ဖတ်လို့ရတုန်း၊ နံပါတ်လည်း ပါတယ်။

ပြီးတော့ ပေါင်းတာက သပ်ရပ်တယ်။ pos 2 က "cat" နဲ့ pos 7 က "cat" ကွာခြားချက်က pos 2 က "dog" နဲ့ pos 7 က "dog" ကွာခြားချက်နဲ့ အတူတူပဲ။ ဒါ့အပြင် ပေါင်းခင် word embedding တွေကို √512 ≈ 22.6 နဲ့ မြှောက်ထားလို့ စာလုံးရဲ့ အဓိပ္ပါယ်က position ထက် အသံပိုကျယ်နေတယ်။

မြှောက်ရင်0.7 × 0 = 0
အချက်အလက် ပျောက်သွားတယ်
0.7 × (−1) = −0.7
ဆန့်ကျင်ဘက် ဖြစ်သွားတယ်
ပေါင်းရင်0.7 + 0 = 0.7
စာလုံး မပြောင်းဘူး
0.7 + (−1) = −0.3
နည်းနည်း ရွေ့သွားရုံပဲ
(cat + PE₂) − (cat + PE₇) = PE₂ − PE₇
(dog + PE₂) − (dog + PE₇) = PE₂ − PE₇
input = embedding × √d_model + PE

အနှစ်ချုပ်

စာလုံးတစ်လုံးချင်းစီရဲ့ နေရာတိုင်းကို အမြန်နှုန်း မတူတဲ့ လက်တံ အများကြီးပါတဲ့ နာရီတစ်လုံး ပေးလိုက်တယ်။ လက်တံတစ်ခုချင်း ဘယ်ညွှန်နေလဲဆိုတာကို ဂဏန်းသေးလေး ၂ ခု (sin, cos) နဲ့ ရေးပြီး စာလုံးရဲ့ encoding မှာ ပေါင်းထည့်လိုက်တယ်။ ဒါကြောင့် model က စာလုံး ဘာလဲ ဆိုတာရော ဘယ်မှာ ရှိလဲ ဆိုတာရော သိသွားတယ်။

နောက်ဆက်တွဲ မှတ်ချက်: BERT နဲ့ GPT-2 လို နောက်ပိုင်း model တွေက sin/cos အစား သင်ယူထားတဲ့ (learned) position embedding ကို သုံးကြတယ်။ ဒီနေ့ LLM အများစုကတော့ RoPE (rotary position embedding) ကို သုံးတယ်။ RoPE က အပေါ်က "လှည့်ခြင်း" idea ကိုပဲ query နဲ့ key vector တွေပေါ်မှာ တိုက်ရိုက် သုံးတာပါ။ ပေါင်းတာ မဟုတ်ဘဲ လှည့်တာဖြစ်ပေမယ့် လှည့်ခြင်းက ဘယ်ဂဏန်းကိုမှ 0 မဖြစ်စေလို့ အချက်အလက် ပျောက်သွားတတ်တဲ့ အားနည်းချက်ကို ဖယ်ပေးနိုင်ပါတယ် (ဒီအပိုင်းကတော့ နောက်မှပေါ့)။
